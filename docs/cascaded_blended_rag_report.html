1.1 System Architecture

The base paper introduces Blended RAG to address retrieval accuracy in question-answering systems. Instead of relying on a single retrieval method, it indexes documents across distinct fields (titles and abstracts) using three complementary search techniques:

Lexical Matching (BM25)
Matches exact terms across title and abstract fields using Best Fields logic. High precision on entity names and abbreviations.
Dense Vectors (KNN)
Sentence embeddings scored through vector similarity. Captures semantic intent when queries lack exact wording.
Sparse Encoders (ELSER / SPLADE)
Learned term expansions that map query words to expanded vocabulary vectors while keeping sparse index efficiency.

1.2 Multi-Field Scoring and Fusion

The paper uses a Best Fields rule for multi-field text: it scores the title and the abstract independently and retains the higher score. Rankings from all three retrievers are combined using Reciprocal Rank Fusion (RRF) with constant k=60:

Score_RRF(d) = sum_{m in {BM25, Dense, SPLADE}} [ 1 / (60 + rank_m(d)) ] Best-Fields Rule: Score_BM25(Q, d) = max( Score_title(Q, d), Score_abstract(Q, d) )

1.3 The Static Execution Problem

The Problem We Target: Blended RAG executes all three retrievers for every query. Simple factual questions pay the exact same 70 to 110 ms latency penalty as complex multi-part questions, even when lexical matching finds the answer on the first pass.

2.2 Methodological Comparison (Paper vs. Reproduction)

The reproduced numbers align with the paper's findings. A few specific metrics came out higher than the original publication for three clear technical reasons:

Open vs. Closed Stack
The paper used IBM's proprietary ELSER index on Elasticsearch Cloud. We used SPLADE-coCondenser, an open-source model with stronger lexical expansion weights.
In-Memory Fusion
Elasticsearch clusters prune candidate lists early per shard to save compute. Our pipeline calculated RRF across all retrieved candidates in memory without early cutoffs.
Candidate Density
Our SQuAD generation test drew from the 2,067 official dev context passages, giving FLAN-T5-XXL fewer out-of-domain distractors than open-web Wikipedia crawls.

2.3 Key Discovery: The Natural Questions Ablation

Measuring each retriever branch individually across 500 NQ queries revealed the core opportunity for efficiency:

BM25 Alone
Achieves 84.40% Top-20 recall in only 10 ms on CPU.
Full Blended RAG
Reaches 97.20% Top-20 recall but requires 67 ms per query.
The Opportunity
For 84% of queries, the lexical pass already finds the answer. Running neural models on those queries adds latency without improving the result.

3.1 Sequential Decision Architecture

Our extension replaces static three-way retrieval with a sequential confidence check. Queries first pass through multi-field BM25. If confidence metrics satisfy the gating threshold, the system returns early. Otherwise, it escalates to full Blended RAG:

Incoming Query Q │ ▼ Tier 1: Multi-Field BM25 Fast-Pass (~10 ms on CPU) │ ├── Check: Top score s1, score margin gap = (s1 - s2), MaxIDF(Q) │ ╱ ╲ Is s1 >= tau_high OR (gap >= tau_gap AND MaxIDF >= tau_idf)? ╱ ╲ YES NO ╱ ╲ ▼ ▼ [EARLY EXIT: Tier 1] [TIER 2: ESCALATE TO BLENDED RAG] Return BM25 Top-K Run Dense MiniLM + SPLADE Cost: ~10 ms (Save 60-80% time) 3-Way Reciprocal Rank Fusion (k=60)

3.2 Cross-Validation and Data Leakage Prevention

A frequent flaw in adaptive retrieval research is tuning thresholds on the full test set. To avoid data leakage, we calibrated gating parameters using 5-fold cross-validation on SciFact. Thresholds were tuned on 80% of queries per fold and evaluated strictly out-of-sample on the remaining 20%.
